# Контроль мастерской, металл и дизайн

## Что добавлено

- /risks/: открытые заказы с просрочкой, отсутствием мастера, отсутствием событий
  N дней (1–90, по умолчанию 7) или незафиксированным согласованием цены.
- В карточке заказа сотрудник с правом approve_price фиксирует согласие клиента
  на текущую цену и основание (квитанция, переписка). Это запись сотрудника,
  не электронная подпись клиента и не автоматическое подтверждение.
- Сумма остатков открытых заказов называется задолженностью. Это не расчёт
  упущенной прибыли. Напоминания по email/мессенджерам пока не отправляются.
- /metals/: отдельные счета по партии, владельцу, цвету и пробе золота.
  Складской остаток, металл в работе, расчётная масса чистого золота.
- /designs/: библиотека карточек, новые варианты с неизменным исходником,
  добавление/удаление элементов и апгрейд как часть задания.
  Экспорт спецификации JSON и шаблонного промпта TXT.
- Фоновые AI-промпты, новые изображения и изменения изображения-референса.
  Без настроенного API нельзя запустить AI: фиктивных результатов нет.

## Обновление существующей установки

Сначала резервная копия базы, затем получить код новой версии и выполнить:
```bash
docker compose build web
docker compose run --rm web python manage.py migrate
docker compose run --rm web python manage.py setup_roles
docker compose up -d web
```

Новая миграция создаёт таблицы приложения workshop, существующие заказы и платежи
не удаляет. До фиксации согласования старые открытые заказы попадают в сигнал
«цена не согласована». Историческое согласие не предполагается автоматически.

setup_roles обновляет стандартные группы: если вы вручную меняли их права,
сначала сохраните вашу матрицу доступа. Назначения сотрудников группам сохраняются.

## Права

Приёмщик дополнительно фиксирует согласование цены и просматривает библиотеку.
Мастер просматривает библиотеку. Новые группы:
- Кладовщик: счета металла и движения, просмотр заказов.
- Дизайнер: библиотека и создание вариантов без платного AI.
- AI-дизайнер: библиотека, варианты и запуск платного AI.

Авторизованные дизайнеры видят общую библиотеку, но не получают доступ к клиентам,
оплатам и металлу. Изображения выдаются защищённым маршрутом, не публичным media URL.
После входа пользователь направляется в доступный ему раздел.

## Учёт металла

received — приход на склад; issued — выдача со склада в работу по заказу;
returned — возврат из работы на склад; consumed — металл в составе изделия;
work_loss — техпотери в работе; loss — списание непосредственно со склада.

consumed и work_loss не списывают склад повторно: он уже уменьшился при issued.
Операции из работы ограничены ещё не закрытым количеством issued по тому же
счёту и заказу. Не допускаются отрицательные массы, повторные токены с другими
данными и отрицательный складской остаток.
Граммы хранятся в Decimal до 0.001 г. Чистое золото = масса сплава × проба / 1000.
Это расчёт, а не результат анализа состава. Масса изделия и движения склада
не синхронизируются автоматически.
Счета разных владельцев не суммируются в общий доступный остаток.

Журнал не заменяет бухгалтерию и нормативный учёт драгоценных металлов.
Движения нельзя удалять через интерфейс. Исправление ошибочного движения —
отдельная подтверждённая обратная операция, если она допускается остатками;
специальный процесс сторнирования пока не реализован.

## Материалы и пределы конструктора

Жёлтое золото: 585, 750, 999. Белое золото: 585 и 750.
Белое 999 не предлагается как стандартный сплав. Покрытие описывается отдельно.
Основания: [GIA о ювелирных сплавах](https://4cs.gia.edu/en-us/blog/buying-guide-white-yellow-rose-gold-engagement-rings/).

Поддерживаются кольца, серьги, подвески, цепи, браслеты, броши, запонки и свободный
«другой формат». Стиль, размеры, камни, закрепка, элементы и пожелания — текстовые.
Сложные и смешанные конструкции описываются в элементах и проверяются мастером;
структурированная спецификация пока хранит один основной сплав на вариант.

Вариант не изменяет исходную карточку. Для реального редактирования внешнего вида
выберите номер готового эскиза этого варианта или его непосредственного родителя.
Без референса генерируется новая интерпретация по тексту, а не точная правка фото.
Загрузка внешних фотографий пока не реализована.
AI может не сохранить все детали точно. Эскиз не CAD/3D-модель и не подтверждение
технологичности, прочности, массы, пробы или цены. Изготовление утверждает ювелир.

## Подключение AI

Требуется API-аккаунт с доступными моделями и разрешённым использованием в вашем
регионе. Подписка на чат сама по себе не настраивает ключ сервера.
В .env задать (не коммитить реальные значения):
```dotenv
OPENAI_API_KEY=
OPENAI_TEXT_MODEL=
OPENAI_IMAGE_MODEL=
AI_DAILY_LIMIT=20
```
OPENAI_TEXT_MODEL — модель Responses API для текстовых промптов;
OPENAI_IMAGE_MODEL — модель GPT Image с поддержкой Images generations/edits
и PNG. Идентификаторы выбираются по доступу вашего аккаунта.
Документация: https://developers.openai.com/api/docs/guides/image-generation

После настройки:
```bash
docker compose --profile ai up -d --build web worker
```

При локальном запуске: python manage.py run_ai_jobs
Один проход: python manage.py run_ai_jobs --once

Ключ не передаётся браузеру. В API отправляются только поля дизайна и, если
выбран, эскиз. Не вводить персональные данные клиентов в поля дизайна.
По умолчанию — не более 3 незавершённых заданий и 20 новых за последние 24 часа
на пользователя. Дополнительно установите бюджет проекта у провайдера;
ограничение количества запросов не является денежным лимитом.

Задания хранят модель, автора, промпт, исходный эскиз, время, результат/ошибку.
Изображение PNG (до 8 МБ) хранится в PostgreSQL; учитывайте объём резервных копий.
API-запрос выполняет worker, не Gunicorn. На PostgreSQL можно запускать несколько
worker; локально с SQLite — только один.
При тайм-ауте автоматического повтора нет: провайдер мог выполнить платный запрос.
При аварийном завершении worker running-задание не отправляется повторно.
Для running старше 30 минут администратор может выполнить:
```bash
docker compose --profile ai run --rm worker python manage.py run_ai_jobs --recover-stale
```
Это отмечает неизвестный результат, а не повторяет генерацию. Новый запуск —
отдельное действие после проверки статуса и расходов у провайдера.

## Проверки

python manage.py test запускает существующие тесты CRM и новые сценарии.
С PostgreSQL дополнительно проверяются конкурентные оплаты и выдача металла.
AI-тесты подменяют ответы провайдера: не отправляют запросы и не тратят средства.
Нужен отдельный smoke-тест реального API после настройки моделей и ключа.
